## 2026-10-29: re-pin, bounded inventory transactions, movement writer, packaging

- **Horizon pin moved** from `e1b2b0b` to `9669600c389ad6d205db4ec0bb061935f2a38d0c` (`nightly-source/2026-10-28-9669600`, Minecraft 26.3 / protocol 777 unchanged). It contains the stable hook points (`360272fd7`, `NATIVE_HOOKS_API` 1) and Windows native builds (`81f339814`). All 23 hooks resolve unchanged; only `tick`, `window_event` and `draw_extras` bodies changed, and only by adding native-hook calls and unrelated host features. Main HEAD `c6af857` (API 2) also planned and compiled, but published mods should pin a tagged Nightly, not an untagged main commit. Evidence: [repin-packaging-eval.json](evidence/repin-packaging-eval.json). Re-pin early and often: every module added against an old pin raises the cost.
- **Stable hook points are only a partial fit.** Tick, frame and corner-HUD could move to `native_tick`/`native_frame`/`native_hud` (tick needs a remote-order scenario first). Key consumption with repeats, GUI window events/rendering, sessions, render geometry, packets, inventory and camera have no stable hook. The bundle therefore keeps an exact pin and cannot declare `"hooks": 1`; moving the three candidates only reduces how many targets can drift.
- **Packaging time-box result.** The launcher's tool pin `0d6b103` and upstream main `3f99a5c` both reject the Game-owned state (`E_BRIDGE_TARGET`). Upstream main additionally rejects four HEAD hooks on macro-bearing bodies: `client-input`, `gui-events`, `gui-render`, `session-connect`. A stock-tool variant (`tools/stock_bundle.py`: one runtime per window thread behind the same accessor) plans and type-checks without those four hooks, including with the launcher's `--features horizon-client/mods`. **Decision needed from the user**, with the options below. Until then the development tool patch stays, and nothing is sent upstream.
  - (a) Offer the lifetime-state patch and a macro-preservation fix upstream to horizon-mixins. This is outward-facing, so it needs explicit approval.
  - (b) Ship the per-window-thread owner. Server and dedicated Games never touch the runtime, but this relaxes the "no thread singleton" rule. Then retarget the four hooks: `client-input` → `native_key_event` (it carries repeat), `gui-render` → `native_frame`/`native_hud`, `session-connect` → a macro-free boundary, `gui-events` → to be determined.
  - Recommendation: (b) for the retargeting, since it removes target drift whichever owner is chosen; (a) for the owner if the user approves an upstream contribution.
- **Inventory transactions are bounded.** Remote `state_id` only moves when the server sends a packet, and a vanilla server sends none when a click matches the client's prediction or does nothing. So waiting for a revision change could hang forever. `inventory::planner::Gate` resolves each click by its visible effect on the clicked slot or the cursor (`Applied`). A revision change with no effect is `NoEffect`; no effect within 1.5 s is `TimedOut`. After a failure the gate is stalled until the session or inventory content differs, because deterministic planners would repeat the same no-op. Planners close only inventories they opened. A runtime watchdog cancels any planner that holds the container claim for 5 s without emitting an effect. AutoFish uses the same gate.
- **One movement-input writer.** `core::movement_input::Writer` is the only code that writes synthetic movement keys. It works from the host's canonical key set: rebinding, controllers and the control socket have already been translated there, and sneak/sprint come from the host's toggle mappings. It reconstructs the user's state from host events (the `mapped_key` and `control_key_down` HEAD adapters) and from changes the host made itself (such as screens clearing keys). It never reads raw physical keys. Modules submit per-tick requests; with no request, an owned axis returns to the user's state. Sprint and Parkour use it. Remaining work: competing-module priorities for SafeWalk/KeepSprint/WTap, and analog controller movement.
- **Module registry is one table** (`src/core/registry.rs`): one line per module generates the enum, `ALL`, ids, names, categories, panel defaults and default binds. Parallel workers each add one line instead of editing five scattered match blocks. `ui/gui.rs` is split into `gui/{mod,input,render}.rs`.
- **Ledger kinds.** `docs/features.csv` has a `kind` column (module, submode, submodule, helper, client, online). The 243 rows whose category discovery left as "inherited/HUD; review" were resolved from the reference text by `tools/ledger_triage.py`, using the `extends` chain to a `Category.*`, ModManager registration and HudModule ancestry. Helper rows (GUI components, controllers, packets, rule classes) are tracked under their owning feature, not as separate deliverables. Remaining work counts modules, submodes and submodules.
- **Ledger status `integrated`** means connected to the real host with fresh-home scenario evidence for the implemented scope, while reference parity remains open. `validated` stays reserved for full-scope host validation.

## 2026-10-29: entity snapshots and AimAssist

- **Frame-driven worker steps.** The reference runs AimAssist's rotation worker on its own thread about every millisecond and applies the accumulated mouse steps once per render frame. The port runs one worker step per elapsed millisecond of the runtime's monotonic clock (at most 100 per frame, so a hitch cannot spin the view) on the render thread. It then applies the render-frame step through the host's `mouse::Rotation::turn`, the same `Entity.turn` that mouse look uses. No extra thread or global state is involved.
- **Hook point.** AimAssist uses a HEAD hook on `pad_look`. It runs right after `apply_mouse_look` and before `render`, so the turn shows in the same frame. This matches the reference `EventPreRenderTick`.
- **Target classes.** The reference's Java class checks are mapped to host spawn categories. Mobs are `monster`, plus slime, magma cube, ghast and ender dragon. Peaceful is `creature` and `axolotls`, plus villager and snow golem. Ambient and other living entities only count when Peaceful is on. "Neutral" has no filtering effect, as in the reference. Team and bot rejection wait for AntiBot, which the reference also requires.
- **Reference quirks kept.** Distance is truncated to whole blocks for target validity. The angle limit is `(int) maxAngle / 2`. The quadrant-atan yaw gives 0 for exactly axis-aligned deltas. Vertical drift jitter applies even with Aim vertically off. The filter summary keeps its double space before `|`.

## 2026-10-29: SafeWalk, TriggerBot and Velocity boundaries

- **SafeWalk uses the move-only edge back-off.** The reference sets `MovementInput.sneak` only around the move, so vanilla's edge check applies but the player never crouches or slows down. Horizon reads that check from `shift_key_down` inside its library-crate motion code. The tool cannot attach owned state to library structs with public fields, and `MovementHistory` has no struct literal to extend. So a library support module adds a public inherent method on `PlayerMotion` backed by a per-thread mark naming that player's address. The binary's movement writer rewrites the mark before every client tick, and the edge hook answers true only for that player. A server Game, guests and mobs on the same thread never match. This is a per-call identity flag, not a shared runtime.
- **TriggerBot's cooldown** reads the client's `hand_strength.ticker` (`attackStrengthTicker`). The integrated server's `attack_ticks` does not move on the client path; the first host run with it landed only one hit in 40 ticks. Attacks are one `KeyMapping.click` through the host input path. The axe-without-HitSwap cooldown bypass stays off until HitSwap/AutoMace exist.
- **Inbound packets are cancellable; holding is bounded and replays through the host.** (Supersedes the earlier observe-only decision: the pinned tool keeps macro bodies under cancellable HEAD when the helper returns `ControlFlow<Result<()>>`.) KnockbackDelay's queue lives in the `vape_packets` support module, holds at most 256 packets, replays through `handle_packet` under a guard, and never holds connection-critical packets. Velocity's replacement of the local motion is still applied right after the host's own assignment, and only if the motion is still exactly what the packet set. Explosions use a separate cancellable hook on the macro-free `remote_explode`.
- **Single player runs only on Horizon's integrated server thread (user decision, 2026-10-29).** Horizon's default single-player mode runs the world on its own server thread and joins it over the same play-packet path that remote servers use. The mod supports and tests only that mode, plus LAN and remote multiplayer. The test tools pin `HORIZON_SERVER_THREAD=1`, have no option for Horizon's alternative frame-loop world, and the mod carries no hooks for it. `session-dimension` and the local knockback/explosion hooks were removed for that reason.

## 2026-10-31: inventory worker, use sequences, InventoryFill, Refill and AutoTotem extras

- **Use sequences are one executor.** Throwpot, ThrowDebuff and AutoHeal Legit share `src/core/throw_runtime.rs`, which holds the hotbar, use and container claims at priority 150. That is above the inventory planners and AutoFish (100) and below macros (200). Effects go through the host's ordinary paths: the selected slot, one use press (`vape_macros::use_once`) and the held-item drop.
  - A manual slot change, an opened screen, a lost claim or disabling the module abandons the sequence without restoring the slot.
  - None of the three rotates, so they do not need the shared rotation owner. The player aims, as with the reference's non-rotating modes.
- **Soup and "Throw bowls".** The reference presses use once. A server with instant soup turns the stew into a bowl, and the bowl is then dropped. On vanilla, stew must be held to eat, so one press does not eat it. The drop runs only when the held item really is a bowl, which means vanilla keeps the stew rather than throwing food away.
- **ThrowDebuff matching.** Potions match by decoded effect id (instant_damage, weakness, poison, slowness) or by a custom name that contains the debuff's name. The reference matches by display name. Matching on effect ids is the same intent in a locale-independent form.
- **AutoHeal is in the "Hidden" category,** as in the reference (`Category.HIDDEN`). It is reachable by bind and config, and the GUI search does not list it.

  - Bowl Mode and Replace use the shared click session, which clicks only inside the player inventory screen. Bowl handling therefore runs only while the inventory is open; Replace opens the inventory itself, as the reference does.
- **InventoryFill** runs in the existing `client-frame` dispatch. While Shift and the left button are physically held over a container screen, it shift-clicks the hovered slot (`Game::slot_at`) at the CPS rate, with the reference's 80 % "remember the slot" roll. It takes the container claim at priority 90 only for the duration of each click.
- **Refill double-click.** The reference sometimes sends a second shift-click on the same slot. We queue it with a 20 % chance and send it only when the source slot still holds a healing item and the hotbar still has an empty slot. A no-op click would be rejected by the gate's revision check anyway, so this sends only clicks that change something.
- **AutoTotem extras.**
  - "Random slot" picks uniformly among the totem slots.
  - "Extra randomization" is the reference's `computeDelay`: a normal centred on the range with sd range/4, clamped to the range, plus an 18 % chance of a long pause of max(120, 1.25·range) to max(350, 3.25·range) ms.
  - "Show totem count" is drawn by the centre-screen active-module stack (see the inventory round-2 entry below).
  - "Silent open" and "Silent move delay" are not registered. `menu_ops` sends server clicks only while `Screen::Inventory` is shown, so clicking the player inventory with no screen open needs a Horizon API. This is blocked; there is no workaround.

## 2026-10-31: HUD modules triage (HUD worker)

- Freelook is blocked on Horizon. The camera rotation comes from `player_camera_entity()` and then `align_with_entity` in `game/perspective.rs`. There is no override point for it: a HEAD hook would have to copy the whole function, and a MODIFY_ARG on the borrowed `CameraEntity` cannot return a changed value. `turn_player` also serves the pad and aim paths. This needs a Horizon camera-rotation hook, and there is no workaround.
- Motion Blur is blocked on Horizon, which needs a frame-accumulation (previous-frame blend) hook. The reference is limited to versions >= 1.17 and < 26.2.
- Blockhit Animation (reference: 1.8.9 only) and Hit Color (reference: > 1.7.10 and < 1.16.5) are not-applicable-reviewed for 26.3.
- Scoreboard and Inventory Blur are retained even though the reference limits them to < 1.20.6. Both are useful on modern versions, and the host draws a sidebar and a menu blur that we can hook.
- Scoreboard is drawn by our HUD panel. It clones the board, blanks the score numbers unless Show score numbers is on, and paints the host's own `hud_overlays::sidebar` draws at the panel position. The `scoreboard-sidebar` HEAD hook cancels the vanilla sidebar only while the module is enabled. The reference text replacements (server IP, title) are not ported.
- Inventory Blur cancels `menu_blur` on the survival/creative inventory with a radius. The radius is the client menu-blur setting when that is at least 1, and 5 otherwise, so the module still blurs when the vanilla option is off.
- Panic stays visible by default, a deviation from its reference `setDefaultVisibility(false)`. Per-module visibility now exists (see below), but Panic ships with an F10 bind that the reference lacks, and a hidden default would turn that bind into a "Hidden Module" refusal toast.
- **Drift checks never move pins.** `xtask drift` and the daily workflow only report. A pin moves in a reviewed commit after the changed hook sources are read and the scenarios pass. A stable release in compatibility-matrix.json is frozen to its pins (enforced by bundle.py); only the development channel follows main.
- **Shipped Rust has no OS capabilities of its own.** The pack-time capability audit forbids sockets, child processes, FFI, `unsafe` and compile-time file embedding in the payload and adapters. Everything reaches the OS through the host. It also forbids the host's own online paths: its HTTP client (`ureq`), server-pack downloads, opt-in telemetry and the play-with-friends relay. URL literals are rejected too, except in doc comments. The only network traffic the mod can cause goes over the game connection the player opened.
- **`horizon-launcher native-build` is the player's step.** Horizon's launcher keeps `native-build` (trusting native mods' code) out of its agent tools as "the player's decision" (launcher/src/cli_tools.rs). Agents therefore reproduce it with tools/launcher_build.py under target/ and never run the launcher command. The installed-launcher run in the release checklist is done by the user.

## 2026-10-31: HUD and client foundation (worker round 2)

- Per-module visibility (`Mod.visible`) follows the reference. Speed, Fly, Timer, InvCleaner, ThrowDebuff, AntiDebuff, InvWalk and AutoHotbar are hidden by default. `modules.<id>.visible` is saved only when it differs from the default. A hidden module refuses its bind with a "Hidden Module" / "Attempted to toggle X!" warning for 2500 ms. A GUI click (for example from search) enables and unhides it. After a profile load, hidden enabled modules that have a Text GUI colour are switched off ("Hidden Disabled"). Modules without a colour stay on, as `getGuiColor() == 0` does in the reference.
- The edit-mode button is 8 units wide and sits just left of the collapse target, because the reference's 16-wide icon would overlap that target. Its hit is registered even when the header is not hovered: the hits come from the last frame, and a click at the button means the pointer is already on the header. The "Edit hidden modules" tooltip waits for the tooltip system. The Favorites frame has no edit mode. The row status pointer triangle is drawn approximately, with fill slices.
- Bind-only modules (the `UtilityMod` subclasses, plus InvCleaner and AutoHotbar while "On Key") refuse GUI clicks. The row shows "MUST BE BOUND" or "USE VIA BIND".
- Blur background reuses the host menu blur through a second cancellable HEAD hook on `Game::menu_blur`, `gui-blur`, rather than a new blur path. It is on while the click GUI or the HUD editor is open, because the reference's `renderGui` is shared by both. It uses the menu blur radius, or 5 when that setting is off, like Inventory Blur. When the setting is off, the hook cancels the Paused screen's own blur.
- Every `Kind::Color` registers a hidden-in-list `<id>.rainbow` boolean, the reference's "<name> rainbow". The colour popup shows it as a fifth Rainbow row. While it is on, the hue advances by Rainbow speed on a per-colour 50 ms timer and wraps to 0 past 255. The colour is converted with Java's `HSBtoRGB`/`RGBtoHSB`. The cycled ARGB is written back without dirtying the profile, so a later save stores the current hue, as the reference's suppressed persistence does. Rainbow colours advance every frame, not only when a module reads them. Our popup still edits ARGB channels, not the reference's hue/saturation/brightness picker.
- TextGuiSettings Scale is 0.1..2.0 in tenths. Rescale is stored, because the reference never reads it. "Match GUI color" uses the fixed GUI accent, because our GUI has no theme colour setting to follow. Click disable is not ported: the reference only handles it while the click GUI is open, and our HUD is not drawn under the GUI yet.
- A cleared ClientSettings GUI bind falls back to Right Shift, as `ClientSettingsGuiBindBendable.setBoundInputs` does, so the GUI cannot become unreachable.

## 2026-10-31: inventory worker round 2, item text matching and the centre stack

- **Item text is the host's tooltip text.** Display name, item name and lore come from `horizon_client::item_tooltip` (`name_line`, `lore_texts`) with the resource pack's translations. Item name is the same line with the custom name removed, which is `getItemStackDisplayName` in the reference. Both sides are lowercased before comparing, as in `TextMatchMode`.
- **Regex is a bounded subset of `java.util.regex`** (`src/inventory/text_regex.rs`). The only dependency is `serde_json`, so there is no regex crate. Literals, classes, groups, alternation, anchors, `\b` and greedy or lazy quantifiers are supported, with whole-input `String.matches` semantics. Lookaround, backreferences and possessive or atomic forms are rejected, which behaves like a `PatternSyntaxException`: the condition never matches, for both "matches" and "does not match". Backtracking has a step budget, so a pathological pattern fails instead of stalling the tick.
- **Active-module stack.** `ActiveModuleStackFrame` is ported as the centre-screen stack in `src/modules/render/center_stack.rs`, with the reference layout: 10 below centre, one font line plus 4 per entry, the label centred, and a grey module-name suffix once there is more than one entry. Its entries are Health and AutoTotem's totem count, in that fixed order. The reference orders by module enable order. Our runtime does not keep an enable order, and with two entries a fixed order is the only visible difference. Scaffold, Clutch, AutoLadder and CrystalAura publish display info in the reference and will join the stack when those modules are ported. The ClientSettings visibility gates (`isInputEnabled`, main GUI stack) belong to the HUD/ClientSettings worker and are not applied here.

## 2026-10-31: inventory worker round 2, planners, ChestSteal and AutoTotem Silent open

- **InventoryManager idles without a profile.** With no profile at all, the module stays on and plans nothing (`shouldSkipProcessing`). It used to fall back to an empty default profile, which still sorted armor. An empty or unknown selection still picks the first profile.
- **Best armor and condensing.** Only a carried armor piece belongs to the armor step. A carried non-armor stack is a condense in progress and goes on to its condense target. The old code put it back at its origin, which looped (host planner scenario, case 5).
- **AutoHotbar "Any material"** takes the rule item's kind (tool/weapon class, armor slot) from the rule id, as the reference compares classes against the rule item itself. It no longer requires a copy of the exact rule item in the inventory.
- **ArmorSwitch reads the worn material from the first worn piece** and needs the whole other set in slots 9-44 (`hasEquippedArmor`/`findArmorSlots`). After an interrupted run that already swapped the helmet, the rerun sees a diamond helmet and an incomplete diamond set, and turns off without a click. This is the reference's behaviour, kept as is.
- **ChestSteal.**
  - "Check in menu" defaults to off, as in the reference. Saved configs that set it keep their value.
  - The old shuffle seed was 0, which made the xorshift degenerate (it never shuffled). The seed is now time-mixed, like Refill's.
  - The distance sort reproduces Java's `countRunAndMakeAscending` plus binary insertion sort with the reference's non-transitive comparator (`d(a)` against `d(b) + 1.0`, from cell (-1, 0)). That is exact for fewer than 32 slots (every chest). Larger lists use the same insertion sort rather than TimSort's merges, which is an approximation.
  - Timing approximations: the first click waits max(travel, 100) ms; an emptied queue is checked one tick later; a click that fails moves on to the next slot. "Keep open" never rescans an open chest, as in the reference.
- **AutoHeal "Inventory Only" is not ported.** AutoHeal.java creates the value but never passes it to `addValue`, so it is hidden and its default (false) is in effect.
- **AutoTotem "Silent open"** (`silentOpen`, default false) and **"Silent move delay"** (`silentMoveDelay`, RandomValue 50..200, default 100-120, step 1) are ported.
  - A silent session swaps the totem through the player menu with no screen (`remote_menu_ops` with `Input::Swap` to button 40 while the screen is Playing).
  - It then closes the player menu with `remote_close_container` (ContainerClose 0). "Close inventory" is hidden while Silent open is on (`unless`), as in the reference.
  - While the session runs and for one fresh "Silent move delay" sample after its last action, movement keys are held: forward, back, left, right, jump and sprint, but not sneak. They are held through the movement writer (owner `AutoTotem`, priority 5), which hands the axes back afterwards. This replaces the reference's explicit key restore. The hold overrides InvWalk's keys.
  - Clicks are held in the same window by three cancellable HEAD hooks on the remote paths: attack (`remote_start_attack`, ordered ahead of `remote-attack`, which also steps aside), use (`remote_use`) and break (`remote_continue_attack`). Single-player runs through these remote paths too.
  - The rotation is held at the sent view while the session is open (`Managed::hold`). On close it returns linearly at speed 0.75, without the controller's randomize jitter, and the AutoTotem claim is released. The reference's thread-bound tick cancels do nothing: callbacks ignore `fire()`'s result and RotationManager doesn't skip cancelled events. So, as there, the held rotation is still sent.
  - `isSilentOpenBlocked` consults only the rotation claim, because Freecam is not ported. As in the reference, the claim is acquired only when another module holds it. The rotation is released only while nobody else owns the claim.
  - A container opened during a session ends it without a close of its own (the container's close puts the server back on the player menu). The reference just waits in that case.
  - **Open:** the reference's `onWindowClick` also cancels the player's own clicks while an AutoTotem-opened (non-silent) inventory screen is shown. That is not ported. Silent sessions have no screen to click, so it doesn't apply to them.
- **Refill watches its screen on every update**, as the reference's per-tick `onTick` does; the click delay paces only the clicks. Seeing the player inventory once marks the run as opened. The first update without it finishes the run (close if a screen is open, then disable), with no delay wait. Before this, a user close inside the first click delay went unseen, and Refill reopened the inventory (host scenario `inventory_scenario.py`, "Refill interrupted").
