# AutoTool and hotbar action ownership

Reference: utility/AutoTool.java, utility/inventory/InventoryActionGuard.java, ItemStackScoreUtil.java and RotationUtil.java at 3d600a48106822755cea2d633062e5ab1f383d48. Read as static text only. AutoTool belongs to World and defaults disabled.

Retained settings: Swap to delay 0–500 ms (default 50, step 50); Swap weapon true; Instant swap true, conditional on Swap weapon; Swap back false; Swap back delay 50–1000 ms (default 350, step 50), conditional on Swap back; Require mouse down true; Only while sneaking false; Not during combat false; Not during use false. No setting or weapon branch is pruned.

Nine hotbar candidates are scored against the actual nearest host crosshair target. Block scores use the host tool/mining-speed data; golden tool scores are halved as in the reference. Candidate score must be finite and strictly greater than 1; ties retain the first slot. Entity candidates retain swords and tool-component items. Modern weapon scoring uses the host's attack-damage modifier and data-driven generic enchantment damage, with the source fire-aspect/sword tie-break amounts. Scoring uses a separate deterministic random instance and never advances world randomness. This uses meaningful attack damage rather than summing unrelated modern attribute rows (including attack speed) as the reconstructed Java helper does. Actual attacks/cooldowns remain entirely in the host.

Timing is simulation tick based, converting configured milliseconds with ceil(ms/50), independent of rendered FPS. This follows plan.md's gameplay deadline contract. Pending swaps are canceled on invalid input/context/guards instead of maturing across a menu or unrelated action. Instant swap bypasses the delay for entity/weapon targets. Swap-back retains the first original slot and schedules a conditional return after the target/trigger disappears; a started return finishes before a new target's swap, matching source order.

A hotbar lease belongs to an owner, client-session generation and monotonic serial. Higher priority may preempt a lease; equal priority preserves the existing owner. A stale release cannot remove the new owner's claim. Native selection requires a current lease, unchanged expected selection and the intended item still present at the destination. Decisions are consumed synchronously on the host thread; no inventory/world references are retained and no item is moved, cloned or deleted.

An actual user hotbar change while a return is owned cancels the return and suppresses repeated switching until the trigger resets or target changes. This honors physical intent and avoids fighting the user. Disabling, panic, profile/session changes and context suspension release claims and discard pending work. A completed selection remains a normal host selection; cleanup does not replay a delayed return into another world. The source has no explicit disable cleanup for its cached slots/timers; carrying those stale values across re-enable is intentionally not reproduced.

The native adapter runs at client tick HEAD, before both integrated/remote input processing, and at the local attack entry for an immediate weapon decision. It updates the same selected field as normal number keys. The remote host input path sends SetCarriedItem before attack/use through its existing codec/connection. This mod does not replace protocol encoding or simulate server acceptance.

Combat guard retains its 20-tick cooldown and five stationary-check release behavior, health loss/hurt cooldown and actual swing-at-entity triggers, nearby nonfriend player checks (10 blocks), and mutual 6-block/60-degree threat checks. Friends honor the local Use Friends and target flag, by name or UUID. LAN guests (when hosting) and remote player mobs are considered. All guard timers/health history reset with session state. Native scenarios now exercise sneak/use/damage guards and weapon selection on both host paths; nearby-player/friend threat combinations still need multi-client validation.

Baseline host evidence covers actual stone destruction and cobblestone drops, diamond tool wear while the penalized golden tool stays unused, swap-back, manual selection, panic, GUI toggle and restart on both host paths. Full typed-editor/tooltips, shared UI fidelity, additional multiplayer server scenarios and cross-module action combinations remain open. Container transaction/state-ID/acknowledgement support is a separate dependency for item-moving modules; hotbar selection is not presented as that full adapter.
